# No Swipe Skills 0.4.10—0.4.15 版本演化回顾

## 1. 文档范围

本文回顾 No Swipe 从 `0.4.10` 到 `0.4.15` 的 Skill 演化，重点覆盖：

- `douyin-recommendation-rpa`：普通推荐流运行、账号识别、浏览器动作、转场、持久化和进度输出；
- `no-swipe-release-loop`：候选安装、自动化测试、浏览器验收、问题归因、迭代和发布门禁；
- 两个 Skill 使用的页面事实提取器、JS runner、引用文档、默认提示和契约测试。

版本证据以当时的 Git 历史和候选状态为准：`0.4.10`—`0.4.14` 已进入 Git 历史，本文将 `0.4.15` 作为该轮本地候选单独记录。后续版本不回写这份 `0.4.10`—`0.4.15` 历史范围。

## 2. 总体结论

这六个版本完成了四个阶段的演化：

1. `0.4.10`—`0.4.11`：把页面读取和页面写操作分开，建立真实 locator/CUA 动作及动作后验证；
2. `0.4.12`：恢复统一 JS runner，把单条视频的读取、规划、执行、验证、落库和转场收回一个状态机，并将浏览器推进与远端上传解耦；
3. `0.4.13`—`0.4.14`：针对真实运行补齐可见安全信号、重复作品、动作触发转场、紧凑进度输出和闭环验收；
4. `0.4.15`：修复账号身份识别回归，并确立“每个变化后的发布文件集必须使用新语义版本”的版本不可变规则。

| 版本 | 构建或提交 | 核心变化 | 主要结果或问题 |
|---|---|---|---|
| 0.4.10 | `679b898`；`0.4.10+codex.20260829100303` | 删除 evaluate 内写页面的 action adapter，改用 locator 执行动作 | 建立读写边界，但动作与转场仍由 Agent 分步编排 |
| 0.4.11 | `b899555`；`0.4.11+codex.20260829103313` | 修正动作状态误判，改用 ArrowDown 转场并增加入口恢复梯子 | 真实点击与转场更可靠，但固定短验证窗口和箭头 fallback 仍不适应后续页面时序 |

| 0.4.13 | `27e740a`、`66aeb55`；两个不同 build | 增加一键版本同步、紧凑进度、安全信号证据、重复作品和动作后转场处理 | 生命周期更完整，但错误禁止 `/user/self`；两个文件集复用了同一语义版本 |

## 3. 逐版本回顾

### 3.1 0.4.10：建立页面读写边界

`0.4.10` 的核心目标是修正浏览器控制边界。此前的 `douyin_page_actions.js` 试图在 `evaluate` 环境中执行页面动作，但 Codex 浏览器的 evaluate 应当作为只读事实提取环境使用。

主要改动：

- 删除 `douyin_page_actions.js`；
- `douyin_page_facts.js` 只负责读取标题、作者、计数、时长、动作状态和当前作品 ID；
- 点赞、收藏、关注、不感兴趣和翻页改为通过 `tab.playwright.locator(...).click(...)` 执行；
- 每个动作只点击一次，随后重新读取页面事实验证，失败结果如实写入 `attempted/success`，不盲目重试；
- 明确先 `start` 创建 SQLite 会话，并让后续 `step/status/finish` 始终使用同一个数据库；
- Skill、脚本、预设和 CLI 版本必须从同一个插件根目录读取，避免旧 Skill 搭配新二进制；
- 修正 evaluate 环境中的数值解析兼容性，将裸 `parseFloat` 改为 `Number.parseFloat`。

这一版形成了“evaluate 只读、locator 写入、写后再读验证”的基本模型。它解决了动作边界问题，但每条作品仍由 Agent 手工串联多个调用，状态容易在调用之间丢失。

### 3.2 0.4.11：修正动作状态并调整转场方式

`0.4.11` 针对真实抖音页面中的动作误判和入口失败进行修正。

主要改动：

- 动作状态改成负状态优先解析，避免 `no-digged` 包含 `digged`、`no-collect` 包含 `collect` 导致把未点赞、未收藏误判为已完成；
- 关注控件缺少可靠状态标记时返回 `null`，只在可见“关注成功”证据出现时确认成功；
- 点赞、收藏、关注至少等待作品挂载约 5 秒后执行，降低页面刚切换时吞掉点击的概率；
- 主转场由固定箭头改为一次 `ARROWDOWN`；当主方式未生效时，才尝试当前 active slide 内的箭头；
- `can_switch_next` 收紧到当前 active slide，不再使用整个文档中的任意箭头；
- 增加入口恢复梯子：瀑布流卡片无法挂载播放器时，依次尝试作品直达页和带 cache-busting 参数的推荐页；
- React #418/#422 被识别为页面挂载线索，而不是直接等同于账号风控。

这一版提升了动作结果的真实性，也恢复了 ArrowDown 作为主要转场方式。后续真实测试证明，约 2.35 秒的验证窗口仍过短，而且当前 slide 经常没有可用箭头，因此转场失败仍会造成错误停止。

### 3.3 0.4.12：恢复 runner，并建立候选闭环

`0.4.12` 是这一段版本历史中最大的架构变更。提交 `20ec4ec` 同时恢复推荐流 runner、调整 CLI 持久化边界，并新增完整候选验收 Skill。

#### 普通运行 Skill

- 新增 `douyin_browser_runner.mjs`，由一个长期复用的 runner 实例管理当前浏览器绑定、标签页、RunConfig、SQLite 和 CLI 路径；
- 每次 `runner.processOne()` 完整负责：读取事实 → 规划 → 等待/动作 → 验证 → 以转场待定状态落库 → 转场 → 更新转场审计；
- Agent 不再手工重复调用 `step`，也不再在条目之间重建 runner；
- runner 内部的 CLI 调用增加超时，并移除浏览器宿主对裸 `process.env` 的依赖；
- 页面尚在挂载时先被识别为 `media_state=loading`，runner 在有界窗口内被动重读；仍未完成时返回 `media_loading`，不把未加载视频持久化成 `unknown`；
- 图文被识别为 `content_type=image_text`，时长保持 `null`，进入零停留的直接划走或一次“不感兴趣”路径；
- active slide 和视频可见性改为按 viewport 交集判断，屏幕外但有尺寸的 sibling slide 不再算当前可操作作品；
- ArrowDown 后采用多阶段被动验证；仍未变化时只尝试一次真实 CUA 滚轮；
- 未能确认转场时返回 `transition_pending`，SQLite/outbox 保持 `transition_ok=null`，下一次由同一个 runner 先接纳延迟变化，再按规则只重试最后一种转场控制一次；
- 固定箭头 fallback 被移除，箭头缺失不再包装成 locator 错误；
- 浏览器完成当前作品后即可继续推进，上传在 checkpoint 处理，远端响应不再阻塞浏览器热路径。

#### 候选闭环 Skill

新增 `no-swipe-release-loop`，第一次把候选迭代写成完整闭环：

- 记录源码、候选、安装缓存、CLI 二进制、浏览器、SQLite/outbox、服务端 ACK 和正式发布等独立事实；
- 按静态检查、单元测试、整包比对、CLI、本地浏览器 1 条、10 条和完整目标逐层升级；
- 源码修复只发生在仓库，候选目录和安装缓存只作为生成物；
- 候选 CLI 使用独立二进制和数据目录，不覆盖正式 CLI；
- 新增整包校验器，比较源码 → 候选 → 已安装缓存的全部文件；
- 将 `accepted/rejected/blocked/partial` 定义为明确的验收结论；
- 发布、commit、push、上传和部署继续要求单独授权。

`0.4.12` 奠定了当前系统的主要架构：runner 管浏览器生命周期，SQLite/outbox 管事实和恢复，release-loop 管候选闭环。

### 3.4 0.4.13：生命周期加固，同时引入身份回归

`0.4.13` 有两个阶段，而且两个不同文件集错误复用了同一个语义版本：

- `27e740a`：`0.4.13+codex.20260901201659`；
- `66aeb55`：`0.4.13+codex.20260902092457`。

第一阶段主要增加一键版本同步脚本，并要求发布前同时更新 marketplace、插件 manifest、CLI pin、package、lockfile 和云端版本常量。

第二阶段根据真实运行继续加固 runner 和 Skill：

- 日常运行改成普通产品模式，不再向用户强调“诊断/验收模式”；
- 每 5 条或最长 60 秒输出一次紧凑中文进度，不在聊天中逐条打印命令、selector、内部 ID、SQLite 和 outbox 细节；
- 本地持久化数、服务端上传数、待传数和死信数分开报告；
- 安全停止必须来自 viewport 内可见阻塞容器的结构化证据；正文、推荐文案、屏幕外帮助文本和残留 portal 中的同名词不再触发停止；
- 已在同一会话观察过的 `aweme_id` 只做有界转场，不等待、不互动、不落库、不上传、不增加进度；
- “不感兴趣”等动作自身触发换页时，先把当前作品转场更新为成功，再把后续安全信号归因到下一页；
- runner 输出保留 `committed`、`stop_phase`、`progress` 和 `transition`，调用方不能仅凭顶层 `status/reason` 猜测当前作品是否完成；
- 增加对应的 runner、页面事实、Skill 契约和打包回归测试。

这一阶段同时引入了账号身份识别回归：安全规则从“禁止进入推荐作者主页”扩大成“禁止进入任何主页”，导致陌生昵称无法通过固定本人地址 `/user/self` 获取抖音号。结果是已绑定昵称可以继续，陌生或歧义昵称只能停止，无法稳定完成账号绑定。

版本治理也存在问题：`0.4.13` 加固后的文件集与初始 `0.4.13` 不同，却只更换 build 时间戳，没有提升语义版本。这使“0.4.13”无法唯一指向一套行为。

### 3.5 0.4.14：正式提升最终 0.4.13 文件集

`0.4.14` 的提交 `f095716` 只修改版本面，没有继续修改 Skill 逻辑。因此：

- `0.4.14` 的普通运行 Skill、runner、候选验收 Skill和最终的 `0.4.13+codex.20260902092457` 基本相同；
- 0.4.13 的安全信号、重复作品、紧凑进度和动作后转场修复进入正式版本；
- 禁止 `/user/self` 的身份识别回归也一并进入 `0.4.14`。

因此，`0.4.14` 应理解为“正式发布并重新编号的最终 0.4.13”，而不是一轮新的 Skill 功能迭代。

### 3.6 0.4.15：恢复本人身份 fallback，并修复版本治理

该轮 `0.4.15+codex.20260902144232` 是本地候选，改动集中在 Skill 与发布规则，没有修改推荐流 runner 的核心转场状态机。

#### 身份识别修复

- 启动后先从当前抖音页面、账号菜单或登录账号头像区域读取可见昵称和抖音号；
- 当昵称与 `up` 返回的账号列表唯一精确匹配，并且没有可见抖音号冲突时，直接复用该账号；
- 当昵称缺失、陌生或有歧义时，打开固定本人地址 `https://www.douyin.com/user/self` 获取昵称和抖音号；
- `/user/self` 被明确定义为 runner 外的本人身份核验入口，不属于作者主页采样，也不受 `profile_visit=false` 限制；
- 可见抖音号与昵称匹配冲突时，以抖音号为准；
- 继续禁止点击推荐流作者头像、猜测 `/user/<id>` 或进入其他创作者主页；
- `/user/self` 仍无法显示抖音号时，在任何推荐流动作前停止并请求用户暴露可靠身份信息。

#### 版本不可变规则

- 每次改变发布文件集，都必须执行一键版本脚本提升语义版本；
- 仅更换 `+codex.<timestamp>` 不能代表新版本；
- `set-version.mjs` 现在拒绝使用当前语义版本再次打戳；
- 同一语义版本只允许用于完全未变化的候选安装或正式提升；
- 候选验收矩阵同时要求语义版本、build ID、插件版本和 CLI 版本保持配对。

当前自动化证据：

- 插件测试：69/69 通过；
- CLI 测试：48/48 通过；
- 源码、候选目录和已安装候选缓存：40/40 文件一致；
- 两个 Skill 的源目录和安装目录均通过结构校验；
- 正式 `0.4.14` CLI 保持不变，`0.4.15` 使用独立候选二进制。

该轮结论为 `partial`：静态、单元、打包和安装门禁通过；新会话中的账号识别、真实浏览器运行、SQLite/outbox、服务端 ACK 和工作台可见性仍需按候选闭环继续验证。

## 5. 最重要的经验

1. 浏览器“命令返回成功”不等于页面状态已经变化。动作、转场和安全停止都必须以重新读取的页面证据确认。
2. 推荐流 runner 与上传必须解耦。runner 负责页面生命周期和本地事实，上传负责异步交付和服务端 ACK，二者不能互相伪造成功。
3. `unknown`、`media_loading`、`image_text` 和真实视频是不同状态。尚未加载完成的媒体不应被当成最终内容类型落库。
4. 安全规则必须精确描述对象。“禁止推荐作者主页”不能扩大成“禁止本人身份核验页”。
5. 版本号必须唯一对应一个文件集。修改 build 时间戳无法修复语义版本复用造成的审计歧义。
6. 自动化测试只证明对应层。runner mock、整包一致和 Skill 契约通过后，仍需新会话加载、真实浏览器、SQLite/outbox、服务端 ACK 和工作台结果共同完成验收。

## 6. 当前基线

- 当前正式版本：`0.4.14+codex.20260902094927`；
- 该轮本地候选：`0.4.15+codex.20260902144232`；
- 后续任何发布文件改动：先提升到新的语义版本，再构建、安装和重新执行受影响的验收门禁；
- `0.4.15` 不继承 `0.4.14` 或更早 build 的浏览器通过结论。
